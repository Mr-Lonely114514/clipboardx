> **项目代号**: ClipBoardX  
> **创建日期**: 2025-01  
> **版本**: v5.0

## 1. 项目背景

### 1.1 现状痛点

| 对比项 | Windows 默认剪切板 | 手机输入法剪切板（如搜狗/百度/讯飞） |
|--------|-------------------|-----------------------------------|
| 历史记录 | ❌ 仅保存最近 1 条 | ✅ 保存全部记录（不删除则永久保留） |
| 记录浏览 | ❌ 不支持 | ✅ 弹出列表，可上下翻页浏览 |
| 按需选择 | ❌ 不支持 | ✅ 点击任意条目即可粘贴 |
| 驻留方式 | 系统级（无 UI） | 输入法面板内常驻 |
| 分类管理 | ❌ 不支持 | ✅ 支持收藏/标记/分类 |

用户在日常 Windows 办公中频繁进行复制粘贴操作，但默认剪切板只能保留最近一次复制的内容，一旦复制新内容，旧内容即被覆盖丢失，严重降低工作效率。

### 1.2 目标

在 Windows 操作系统上实现一套**类手机输入法剪切板**的桌面端剪切板管理器，满足以下核心诉求：

- 自动监听并保存所有复制/剪切操作的历史记录
- 提供全局快捷唤起的剪切板面板（类似手机输入法的弹出列表）
- 支持在历史记录中浏览、搜索、选中并粘贴
- 记录持久化保存（SQLite 本地存储，重启不丢失）
- 支持可配置的最大保留条数（默认 5000 条，可设为无限制）
- 轻量、无侵入、低资源占用

## 2. 功能需求

### 2.1 核心功能（P0 - 必须实现）

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-01 | 剪切板历史记录自动捕获 | 监听系统 Clipboard 变化（通过 `WM_CLIPBOARDUPDATE`），自动保存每次复制/剪切的内容。<br><br>**格式处理**：<br>1. **纯文本优先**：从剪切板中提取纯文本内容存入 `content_text`<br>2. **图片备份**：若剪切板中同时包含图片格式，将图片二进制数据存入 `content_blob`（此为 F-14 图片预览的前置数据需求，通过特性开关控制，参见下文"图片存储开关"）<br>3. **兜底逻辑**：<br>   - 若图中无文本，仅有图片 → 仅保存图片至 `content_blob`，`content_text` 为空<br>   - 若有文本但无图片 → 仅保存文本至 `content_text`，`content_blob` 为空<br>   - 若文本和图片均不存在 → 按优先级降序（HTML > RTF > 其他）保留一种可用格式<br><br>**content_type 取值规则**（多格式共存场景）：<br>- 纯文本 + 图片共存 → `content_type = 'text'`（因为纯文本一定存在）<br>- 仅图片 → `content_type = 'image'`<br>- 仅文本 → `content_type = 'text'`<br>- 仅文件路径 → `content_type = 'file'`<br><br>**图片存储开关**（关联 F-14）：<br>- 图片备份存储行为受独立特性开关控制，默认开启<br>- 关闭后，多格式共存时仅保留纯文本，不再向 `content_blob` 写入图片数据<br>- 该开关在 F-14（P2）未实现时可关闭以减少存储占用；F-14 实现后建议开启以提供图片预览数据<br><br>**写回跳过机制**（内存标记方案）：<br>当程序自身将内容写回系统剪切板时，必须设置内存标记位，监听器检测到标记后跳过本轮捕获。异常安全要求：写回过程中若发生异常，标记位必须在 finally/Defer 块中被正确清除，防止标记泄漏导致后续监听失效。**推荐使用内存标记（标志位）而非实际暂停监听器**，以减少窗口竞争条件。<br><br>**监听器生命周期**：暂停/恢复操作必须覆盖"将内容写入系统剪切板"这一原子操作的全过程。暂停时机为**写入前一刻**，恢复时机为**写入完成后立即**，确保中间无其他剪切板变更事件被误捕获。 | P0 |
| F-02 | 历史记录持久化存储 | 所有记录保存到本地 SQLite 数据库，程序重启后不丢失。 | P0 |
| F-03 | 全局热键唤起面板 | 用户按自定义热键弹出剪切板面板。**默认热键改为 `Alt+V`**（避免与 Windows 系统内置 `Win+V` 冲突）。备选方案：`Ctrl+Shift+Insert`。首次启动时检测默认热键是否被系统或其他程序占用，若被占用则提示用户重新设置。（热键冲突检测仅在程序启动时执行一次。） | P0 |
| F-04 | 记录浏览与选择 | 面板内按时间倒序展示记录列表。点击任意条目时的行为：<br><br>**交互模式设置**：支持两种交互模式，默认模式为**自动粘贴模式**：<br><br>- **自动粘贴模式（默认）**：单击某条记录 → 写回跳过机制（参见 F-01）→ 将该记录写入系统剪切板 → 隐藏面板 → 恢复焦点到原活动窗口 → 模拟 `Ctrl+V` 自动粘贴<br><br>- **确认后粘贴模式**：<br>  ① 单击某条记录 → 写回跳过机制（参见 F-01）→ 将该记录写入系统剪切板（不隐藏面板，不自动粘贴）→ 面板保持显示<br>  ② 用户可在面板保持期间自由切换目标窗口（此时双击/回车时以**当前前台窗口**为目标）<br>  ③ 用户双击某条记录或按回车 → 写回跳过机制（参见 F-01）→ 将该记录写入系统剪切板 → 隐藏面板 → 恢复焦点到**当前前台窗口** → 模拟 `Ctrl+V` 自动粘贴<br><br>用户可在设置中切换交互模式。 | P0 |
| F-05 | 记录删除 | 支持单条删除与清空全部历史。清空全部历史时需弹出二次确认对话框。 | P0 |
| F-06 | 系统托盘驻留 | 程序启动后在系统托盘中运行。托盘右键菜单至少包含：显示剪切板面板、设置、关于、退出。支持托盘图标左键单击直接弹出面板。 | P0 |

### 2.2 增强功能（P1 - 建议实现）

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-07 | 记录类型识别 | 区分文本、图片、文件路径等类型，面板中显示类型图标。类型检测规则：<br><br>**① 文件路径（CF_HDROP）**：Windows 资源管理器中复制文件时，系统通过 **CF_HDROP** 格式传递文件路径列表。监听器应检测剪切板中是否包含 CF_HDROP 格式：<br>&emsp;- 若检测到 CF_HDROP → 提取文件路径列表（取首个文件路径）→ 存入 `content_text` → `content_type` 设为 `'file'`<br>&emsp;- 同时检查剪切板是否还包含其他格式（如 CF_TEXT），此时按 F-01 格式处理策略保留优先级最高的格式数据<br><br>**② 文本路径检测**：文本内容以盘符路径（如 `C:\`、`D:\`）或 UNC 路径（`\\`）开头 → 调用 `Path::exists()` 或 `GetFileAttributesW` 验证路径是否真实存在，仅当路径实际存在时才标记为"文件路径"并设置 `content_type = 'file'`，否则按普通文本处理（`content_type = 'text'`）<br><br>**③ 图片/位图数据**：标记为 `'image'`<br><br>**④ 其余纯文本**：标记为 `'text'`<br><br>**显示优先级**（面板中的类型图标展示）：文本 > 图片 > 文件路径。此优先级仅用于面板展示层，不改变 storage 层 `content_type` 的取值。<br><br>**存储字段约定**: `content_type = 'file'` 时，文件路径字符串存入 `content_text` 字段；`content_type = 'image'` 时，图片二进制数据存入 `content_blob` 字段。 | P1 |
| F-08 | 收藏/置顶 | 将常用记录标记为收藏，置于列表顶部。收藏状态持久化保存。 | P1 |
| F-09 | 搜索过滤 | 在面板内输入关键词实时过滤历史记录。**搜索范围**: 联合搜索 `content_text`（文本内容）和 `source_app`（来源应用名称）。**匹配模式**: 采用模糊搜索（推荐 SQLite FTS5 全文索引），支持大小写不敏感匹配，不支持正则表达式（v1）。搜索性能需满足 NF-03 面板响应指标。<br><br>**非文本内容搜索**: 对于 `content_text` 为空的记录（如图片类型），搜索不匹配任何关键词，这些记录不会出现在搜索结果中。注意：多格式共存场景下 `content_type = 'text'` 但 `content_blob` 非空的记录，其 `content_text` 非空可以参与搜索；但 FTS5 不索引 BLOB 列，因此图片内容本身不可被搜索。此行为在用户界面中应通过占位文字（如"搜索仅支持文本及文件路径内容"）向用户说明。文件路径类型记录（`content_type = 'file'`）可通过对 `content_text` 中的路径字符串进行 FTS5 搜索。 | P1 |
| F-10 | 记录数量限制 & 自动清理 | 用户可设置最大保留条数。**默认值为 5000 条**，超出后自动淘汰最旧记录（按 `created_at` 升序淘汰）。用户可设为 **-1**（设置界面显示为"无限制"）以禁用限制，此时所有记录永久保留。<br><br>**无限制模式的安全防护**：<br>1. 系统自动监控数据库文件大小，当文件超过 **1 GB** 时，弹出系统通知警告用户磁盘空间占用过高<br>2. 当记录数超过 **100,000 条** 时，系统自动切换为 FIFO 淘汰模式（忽略用户的无限制设置），并通知用户此行为<br>3. 用户可在警告后主动清理或调整条数限制<br><br>**性能说明**: 当记录数超过 10,000 条时，系统不会崩溃，但面板加载、搜索响应等操作性能会逐步下降（10,000 条以上不再受 NF-03 性能指标保证）。建议普通用户保持默认值 5000 条，仅高级用户在了解性能影响后选择无限制模式。<br><br>配置项位于设置窗口的存储相关分组中。 | P1 |
| F-11 | 窗口焦点自动粘贴 | 按两步法实现：面板带焦点供浏览选择 → 选择记录后隐藏面板 → 恢复焦点到原活动窗口 → 模拟 `Ctrl+V` 粘贴。面板弹出时使用 `WS_EX_NOACTIVATE` 风格以避免夺取焦点（仅置顶显示），用户选择后才隐藏面板并恢复原窗口焦点。 | P1 |
| F-17 | 忽略应用列表 | 允许用户设置"忽略应用"列表，在被忽略的应用中的复制操作**不被**记录。配置方式支持：① 窗口标题匹配（支持通配符）；② 进程名称（exe 名称）匹配；③ 完整路径匹配。<br><br>**匹配策略**（按精确度从高到低，可短路）：进程名匹配 → 完整路径匹配 → 窗口标题匹配。若进程名已匹配成功，则无需继续检查窗口标题。<br><br>**性能考量**: 规则数量上限建议不超过 50 条；50 条规则下的单次匹配耗时应在 1ms 以内。规则更新后应刷新缓存（如进程名 → 完整路径的映射表），避免每次剪贴板变更都重新解析配置。<br><br>**命名说明**: 该功能原称"应用白名单"，因实际语义为"黑名单"（列表中的应用不记录），v3 已更名为"忽略应用列表"以避免语义歧义。<br><br>该功能是第 6 节隐私风险缓解措施的具体实现。 | P1 |
| F-18 | （已删除，内容合并至 NF-06） | — | — |

## 3. 非功能需求

| 编号 | 需求 | 指标 | 验证手段 |
|------|------|------|---------|
| NF-01 | 启动速度 | 程序启动到托盘驻留 ≤ 1 秒 | 在 CI 环境中运行启动计时测试（从 `main()` 入口到托盘图标显示），连续 5 次平均耗时 ≤ 1s，单次不超过 1.5s |
| NF-02 | 内存占用 | **纯文本场景**：空闲状态下内存占用 ≤ 30 MB。<br>**图片存储开启场景**（F-01 图片存储开关开启时）：空闲状态下内存占用 ≤ 80 MB（以 100 条记录的图片缓存为基准，前提是面板中仅惰性加载当前可见项的预览图，`content_blob` 不全部加载到内存）。<br><br>**变更说明**: v2 曾放宽至 50 MB，v3 回归 v1 的 30 MB 指标。v5 根据 S-01 审议明确：30MB 适用于纯文本场景；图片存储开启时调整为 80MB，且依赖惰性加载策略保障。 | — |
| NF-03 | 面板响应 | ① 热键唤起面板：从热键按下到面板首帧渲染完成 ≤200ms（不区分冷启动/热启动，均以首帧渲染为准）；② 列表滚动：纯文本列表 60fps，图片内容 ≥30fps；③ 10,000 条记录下首次从数据库加载完成 ≤500ms。<br><br>**说明**: 10,000 条为性能保证上限，用户默认配置为 5000 条（参见 F-10）。存储记录超过 10,000 条时性能可能下降，超出部分的加载时间不在 NF-03 保证范围内。 | 使用高精度计时器在 CI 中编写性能基准测试，每次构建自动比对基线值。 |
| NF-04 | 存储上限 | 存储上限 ≥ 10,000 条文本记录（受用户配置限制，默认上限 5,000 条，参见 F-10）。**用户设置为"-1 无限制"时，NF-04 指标不适用**，系统行为以 F-10 的安全防护机制为准。 | — |
| NF-05 | 兼容性 | 支持 Windows 10 1903+ 和 Windows 11 | — |
| NF-06 | 安全性 | ① 不收集用户隐私数据；② 除云同步功能外，程序**不建立任何网络连接**；③ 本地数据库采用明文 SQLite 存储（不加密），但需在首次启动时明确告知用户存储安全模型；④ 程序编译时通过代码审查确保无隐藏网络调用依赖，审查范围包括：所有依赖库的网络能力声明、项目代码中的网络 API 调用（如 `reqwest`、`hyper`、`winhttp` 等），审查结果记录在构建流程中。 | ① 通过抓包工具（Wireshark/Fiddler）验证无外发网络请求；② 代码审查记录纳入构建流程。 |
| NF-07 | 可靠性 | 7×24 小时稳定运行，不崩溃、不泄漏 | — |

## 4. 项目结构设计

### 4.1 技术选型建议

| 层级 | 技术方案 | 说明 |
|------|---------|------|
| 编程语言 | **Rust** 或 **C# (WPF)** | Rust 性能好、体积小；C# WPF 开发效率高、Windows 生态好 |
| UI 框架 | **Rust: egui / Tauri**；**C#: WPF / WinUI 3** | 面板 UI 需要支持全局弹出、半透明、焦点穿透等特性 |
| 剪切板监听 | **Rust: clipboard-win + win32 API**；**C#: System.Windows.Clipboard + Win32 API** | 需通过 Windows 消息循环监听 WM_CLIPBOARDUPDATE，并处理 CF_HDROP 等标准格式 |
| 数据存储 | **SQLite**（通过 rusqlite 或 Microsoft.Data.Sqlite），搜索建议启用 FTS5 全文索引 | 轻量、零配置、嵌入式 |
| 全局热键 | **Rust: global-hotkey**；**C#: RegisterHotKey Win32 API** | 注册系统级快捷键 |
| 构建工具 | **Rust: cargo**；**C#: MSBuild / dotnet build** | - |

> **推荐方案**: Rust + egui + SQLite + tray-icon，打包为单个可执行文件，体积小、免安装。

### 4.3 数据表结构（v5 修订版）

**表名**: `clip_records`

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | 自增主键 |
| content_hash | TEXT UNIQUE | 内容哈希值（SHA256 或 MurmurHash），用于去重（配合 UNIQUE 约束，防止短时间内相同内容重复存储） |
| content_type | TEXT | 内容类型：`text` / `image` / `file`。**多格式共存时的取值规则**：若纯文本存在 → `'text'`；仅图片 → `'image'`；仅文件路径 → `'file'`。参见 F-01 完整规则。 |
| content_text | TEXT | 文本内容（`content_type = 'text'` 时存储）；文件路径（`content_type = 'file'` 时存储文件路径字符串，来源包括 CF_HDROP 提取和文本路径检测两种方式） |
| content_blob | BLOB | 二进制内容（`content_type = 'image'` 时存储图片数据）；多格式共存时，F-01 存储策略保留的图片备份也存入此字段。**说明**：此字段主要为 F-14（P2 图片预览）预留数据，受 F-01 图片存储开关控制。关闭图片存储开关后，此字段不再写入新数据。 |
| source_app | TEXT | 来源应用名称（可选） |
| source | TEXT | 记录来源枚举值：`local_clipboard`（用户手动复制）/ `cloud_sync`（云同步）。**注意**: 程序自身写回剪切板的操作通过 F-01 的跳过机制（内存标记）阻止被重复记录，因此不需要 `app_writeback` 枚举值。 |
| is_favorite | INTEGER DEFAULT 0 | 是否收藏 (0/1) |
| created_at | DATETIME DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME DEFAULT CURRENT_TIMESTAMP | 更新时间 |

> **v4 → v5 变更**: 
> 1. `content_type` 补充多格式共存时的取值规则说明
> 2. `content_text` 说明补充"来源包括 CF_HDROP 提取和文本路径检测两种方式"
> 3. `content_blob` 补充"为 F-14 预留"及"受图片存储开关控制"的说明

**全文搜索索引**（可选，建议 FTS5）：

```sql
CREATE VIRTUAL TABLE clip_records_fts USING fts5(
    content_text, source_app,
    content='clip_records',
    content_rowid='id'
);
```

> 启用 FTS5 全文索引可支持高效模糊搜索，满足 NF-03 响应指标。注意：FTS5 仅索引 `content_text` 和 `source_app` 两列，图片等非文本内容（BLOB 列）不参与搜索。

## 5. 交互流程

### 5.1 用户操作流程

```
用户操作                 系统响应
─────────               ─────────
1. 用户复制内容 (Ctrl+C) → 系统剪切板更新
（场景包括:）             → 监听器捕获变更
  a. 复制文本             → 检查应用忽略列表（F-17）
  b. 复制图片             → 检查 content_hash 是否已存在（去重）
  c. 复制文件(CF_HDROP)  → 若为新内容，按 F-01 格式处理策略存储：
  d. 文本+图片共存          · 检测 CF_HDROP → 提取文件路径
                           · 提取纯文本 → 存入 content_text
                           · 提取图片（若开启图片存储开关）→ 存入 content_blob
                          → 写入 SQLite（source = local_clipboard）
                          → 更新面板列表（若有缓存）

2. 用户按下全局热键       → 剪切板面板弹出（WS_EX_NOACTIVATE，不夺取焦点）
                          → 从数据库加载历史记录（按时间倒序）
                          → 渲染列表，首帧完成时间 ≤200ms

3. 用户浏览/搜索          → 实时过滤列表
                          （联合搜索 content_text + source_app，FTS5 模糊匹配）
                          content_text 为空的记录不参与搜索，
                          界面提示"搜索仅支持文本及文件路径内容"

4a. 用户单击某条记录      → [自动粘贴模式 - 默认]
    （自动粘贴模式）         → 写回跳过机制（参见 F-01）
                           → 将该记录写入系统剪切板
                           → 隐藏面板
                           → 恢复焦点到原活动窗口
                           → 模拟 Ctrl+V 自动粘贴

4a'. 用户单击某条记录     → [确认后粘贴模式]
    （确认后粘贴模式）       → 写回跳过机制（参见 F-01）
                           → 将该记录写入系统剪切板（不隐藏面板，不自动粘贴）
                           → 面板保持显示，等待用户双击或按回车
                           （用户可在面板保持期间自由切换目标窗口）

4b. 用户双击/按回车       → [确认后粘贴模式]
                          → 写回跳过机制（参见 F-01）
                          → 将该记录写入系统剪切板
                          → 隐藏面板
                          → 恢复焦点到**当前前台窗口**（而非单击时记录的窗口）
                          → 模拟 Ctrl+V 自动粘贴

4c. 用户删除某条记录      → 从数据库删除
                          → 列表实时更新

5. 用户再次按热键/ESC    → 面板隐藏
```

## 6. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Windows 剪切板 API 限制 | 某些应用使用自定义剪切板格式，可能无法捕获 | 回退到定时轮询 + 支持多种标准格式（CF_TEXT、CF_HDROP、CF_DIB 等） |
| 全局热键冲突 | 与其他软件热键冲突导致功能失效 | 提供可自定义热键 + 首次启动时热键冲突检测 |
| 写入回触发监听循环 | 写回剪切板触发监听器，导致重复数据 | 使用内存标记跳过自触发（参见 F-01 写回跳过机制）；标记位必须在 finally/Defer 块中被正确清除 |
| 面板焦点管理 | 面板夺取焦点后无法自动粘贴到目标窗口 | 采用两步法：面板不夺取焦点（`WS_EX_NOACTIVATE`）→ 选择后隐藏面板 → 恢复焦点 → 模拟 Ctrl+V（参见 F-11） |
| 隐私顾虑 | 用户不希望敏感内容被记录 | 提供"忽略应用列表"功能（F-17）+ 一键清空 + 本地存储不上传 + 首次运行告知存储安全模型 |
| 高频率复制导致性能问题 | 连续快速复制触发大量数据库写入 | 防抖去重（content_hash UNIQUE 约束）+ 异步写入 |
| 无限制模式磁盘空间膨胀 | 用户设为 -1 后数据库持续增长 | 自动监控数据库文件大小（超 1GB 警告）+ 超 100,000 条自动降级为 FIFO（参见 F-10） |
| 图片存储内存占用 | F-01 图片存储开启后 content_blob 数据可能推高内存 | NF-02 明确图片场景内存指标（≤80MB）+ 惰性加载策略（仅加载当前可见项的预览图） |
