## 1. 项目背景

### 1.1 现状痛点

| 对比项 | Windows 默认剪切板 | 手机输入法剪切板（如搜狗/百度/讯飞） |
|--------|-------------------|-----------------------------------|
| 历史记录 | ❌ 仅保存最近 1 条 | ✅ 保存全部记录（不删除则永久保留） |
| 记录浏览 | ❌ 不支持 | ✅ 弹出列表，可上下翻页浏览 |
| 按需选择 | ❌ 不支持 | ✅ 点击任意条目即可粘贴 |
| 驻留方式 | 系统级（无 UI） | 输入法面板内常驻 |
| 分类管理 | ❌ 不支持 | ✅ 支持收藏/标记/分类 |

用户在日常 Windows 办公中频繁进行复制粘贴操作，但默认剪切板只能保留最近一次复制的内容，一旦复制新内容，旧内容即被覆盖丢失，严重降低工作效率。

### 1.2 目标

在 Windows 操作系统上实现一套**类手机输入法剪切板**的桌面端剪切板管理器，满足以下核心诉求：

- 自动监听并保存所有复制/剪切操作的历史记录
- 提供全局快捷唤起的剪切板面板（类似手机输入法的弹出列表）
- 支持在历史记录中浏览、搜索、选中并粘贴
- 记录持久化保存（默认保留最近 5000 条，可关闭限制）
- 轻量、无侵入、低资源占用

## 2. 功能需求

### 2.1 核心功能（P0 - 必须实现）

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-01 | 剪切板历史记录自动捕获 | 监听系统 Clipboard 变化（通过 `WM_CLIPBOARDUPDATE`），自动保存每次复制/剪切的内容。需明确格式处理优先级：**纯文本 > HTML > RTF > 图片**，多格式共存时按优先级选取最高格式存储。<br><br>**写回跳过机制**: 当程序自身将内容写回系统剪切板时，必须通过以下方式之一跳过本轮监听，防止无限循环：① 写回前暂停监听器，写回完成后再恢复；② 通过内存标记/自定义剪切板格式标识本轮写入为"自触发"，监听器检测到后跳过。 | P0 |
| F-02 | 历史记录持久化存储 | 所有记录保存到本地 SQLite 数据库，程序重启后不丢失。**默认保留最近 5000 条记录**，用户可在设置中关闭此限制（设为 0 即不限制）。当达到上限且限制开启时，自动淘汰最旧记录。 | P0 |
| F-03 | 全局热键唤起面板 | 用户按自定义热键弹出剪切板面板。**默认热键改为 `Alt+V`**（避免与 Windows 系统内置 `Win+V` 冲突）。备选方案：`Ctrl+Shift+Insert`。首次启动时检测默认热键是否被系统或其他程序占用，若被占用则提示用户重新设置。 | P0 |
| F-04 | 记录浏览与选择 | 面板内按时间倒序展示记录列表。点击任意条目时的行为：① 将选中内容写回系统剪切板（写回时触发跳过机制，参见 F-01）；② 面板隐藏；③ 恢复焦点到原活动窗口；④ 模拟 `Ctrl+V` 自动粘贴。支持交互模式设置：单击复制到剪切板（不自动粘贴），双击/回车触发自动粘贴。 | P0 |
| F-05 | 记录删除 | 支持单条删除与清空全部历史。清空全部历史时需弹出二次确认对话框。 | P0 |
| F-06 | 系统托盘驻留 | 程序启动后在系统托盘中运行。托盘右键菜单至少包含：显示剪切板面板、设置、关于、退出。支持托盘图标左键单击直接弹出面板。 | P0 |

### 2.2 增强功能（P1 - 建议实现）

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-07 | 记录类型识别 | 区分文本、图片、文件路径等类型，面板中显示类型图标。类型检测规则：① 文本内容以盘符路径（如 `C:\`、`D:\`）或 UNC 路径（`\\`）开头 → 标记为"文件路径"；② 图片/位图数据 → 标记为"图片"；③ 其余纯文本 → 标记为"文本"。若剪切板同时包含多种格式，按"文本 > 图片 > 文件路径"优先级显示内容。图标集参考 Ditto 等成熟工具的标准集。 | P1 |
| F-08 | 收藏/置顶 | 将常用记录标记为收藏，置于列表顶部。收藏状态持久化保存。 | P1 |
| F-09 | 搜索过滤 | 在面板内输入关键词实时过滤历史记录。**搜索范围**: 联合搜索 `content_text`（文本内容）和 `source_app`（来源应用名称）。**匹配模式**: 采用模糊搜索（推荐 SQLite FTS5 全文索引），支持大小写不敏感匹配，不支持正则表达式（v1）。搜索性能需满足 NF-03 面板响应指标。 | P1 |
| F-10 | 记录数量限制 & 自动清理 | 用户可设置最大保留条数。**默认值为 5000 条**，超出后自动淘汰最旧记录。用户可设为 0 以禁用限制，此时所有记录永久保留（需用户自行管理存储空间）。 | P1 |
| F-11 | 窗口焦点自动粘贴 | 按两步法实现：面板带焦点供浏览选择 → 选择记录后隐藏面板 → 恢复焦点到原活动窗口 → 模拟 `Ctrl+V` 粘贴。面板弹出时使用 `WS_EX_NOACTIVATE` 风格以避免夺取焦点（仅置顶显示），用户选择后才隐藏面板并恢复原窗口焦点。 | P1 |
| F-17 | 应用白名单/黑名单 | 允许用户设置"忽略应用"白名单/黑名单，在白名单中的应用内的复制操作**不被**记录。配置方式支持：① 窗口标题匹配（支持通配符）；② 进程名称（exe 名称）匹配；③ 完整路径匹配。该功能是第 6 节隐私风险缓解措施的具体实现。 | P1 |

## 4. 项目结构设计

### 4.1 技术选型建议

| 层级 | 技术方案 | 说明 |
|------|---------|------|
| 编程语言 | **Rust** 或 **C# (WPF)** | Rust 性能好、体积小；C# WPF 开发效率高、Windows 生态好 |
| UI 框架 | **Rust: egui / Tauri**；**C#: WPF / WinUI 3** | 面板 UI 需要支持全局弹出、半透明、焦点穿透等特性 |
| 剪切板监听 | **Rust: clipboard-win + win32 API**；**C#: System.Windows.Clipboard + Win32 API** | 需通过 Windows 消息循环监听 WM_CLIPBOARDUPDATE |
| 数据存储 | **SQLite**（通过 rusqlite 或 Microsoft.Data.Sqlite），搜索建议启用 FTS5 全文索引 | 轻量、零配置、嵌入式 |
| 全局热键 | **Rust: global-hotkey**；**C#: RegisterHotKey Win32 API** | 注册系统级快捷键 |
| 构建工具 | **Rust: cargo**；**C#: MSBuild / dotnet build** | - |

> **推荐方案**: Rust + egui + SQLite + tray-icon，打包为单个可执行文件，体积小、免安装。

### 4.3 数据表结构（v2 修订版）

**表名**: `clip_records`

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | 自增主键 |
| content_hash | TEXT UNIQUE | 内容哈希值（SHA256 或 MurmurHash），用于去重（配合 UNIQUE 约束，防止 500ms 内相同内容重复存储） |
| content_type | TEXT | 内容类型：text / image / file |
| content_text | TEXT | 文本内容（text 类型时存储） |
| content_blob | BLOB | 二进制内容（image 等类型时存储） |
| source_app | TEXT | 来源应用名称（可选） |
| source | TEXT | 记录来源枚举值：`local_clipboard`（用户手动复制） / `app_writeback`（程序写回） / `cloud_sync`（云同步）。用于从数据层面区分记录来源，配合 F-01 的写入回跳机制防止循环。 |
| is_favorite | INTEGER DEFAULT 0 | 是否收藏 (0/1) |
| created_at | DATETIME DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME DEFAULT CURRENT_TIMESTAMP | 更新时间 |

> **v1 → v2 变更**: 新增 `content_hash`（去重）、`source`（记录来源追踪）两个字段。

**全文搜索索引**（可选，建议 FTS5）：

```sql
CREATE VIRTUAL TABLE clip_records_fts USING fts5(
    content_text, source_app,
    content='clip_records',
    content_rowid='id'
);
```

> 启用 FTS5 全文索引可支持高效模糊搜索，满足 NF-03 响应指标。

## 5. 交互流程

### 5.1 用户操作流程

```
用户操作                 系统响应
─────────               ─────────
1. 用户复制文本 (Ctrl+C)  → 系统剪切板更新
                          → 监听器捕获变更
                          → 检查 content_hash 是否已存在（去重）
                          → 若为新内容，写入 SQLite（source = local_clipboard）
                          → 更新面板列表（若有缓存）

2. 用户按下全局热键       → 检测热键是否被占用（首次运行时）
                          → 剪切板面板弹出（WS_EX_NOACTIVATE，不夺取焦点）
                          → 从数据库加载历史记录（按时间倒序）
                          → 渲染列表，首帧完成时间 ≤200ms

3. 用户浏览/搜索          → 实时过滤列表
                          （联合搜索 content_text + source_app，FTS5 模糊匹配）

4a. 用户点击某条记录      → 暂停剪切板监听器（或设置内存标记）
                          → 将该记录写入系统剪切板
                          → 恢复监听器（或清除标记）—— 防止自触发写入回环
                          → 隐藏面板
                          → 恢复焦点到原活动窗口
                          → 模拟 Ctrl+V 自动粘贴

4b. 用户双击某条记录      → 同 4a（与单击行为相同，具体由用户配置决定）

4c. 用户删除某条记录      → 从数据库删除
                          → 列表实时更新

5. 用户再次按热键/ESC    → 面板隐藏
```

## 6. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Windows 剪切板 API 限制 | 某些应用使用自定义剪切板格式，可能无法捕获 | 回退到定时轮询 + 支持多种格式 |
| 全局热键冲突 | 与其他软件热键冲突导致功能失效 | 提供可自定义热键 + 首次启动时热键冲突检测 |
| 写入回触发监听循环 | 写回剪切板触发监听器，导致重复数据 | 使用暂停/恢复机制或内存标记跳过自触发（参见 F-01 写回跳过机制） |
| 面板焦点管理 | 面板夺取焦点后无法自动粘贴到目标窗口 | 采用两步法：面板不夺取焦点（`WS_EX_NOACTIVATE`）→ 选择后隐藏面板 → 恢复焦点 → 模拟 Ctrl+V（参见 F-11） |
| 隐私顾虑 | 用户不希望敏感内容被记录 | 提供"应用白名单/黑名单"功能（F-17）+ 一键清空 + 本地存储不上传 + 首次运行告知存储安全模型 |
| 高频率复制导致性能问题 | 连续快速复制触发大量数据库写入 | 防抖去重（content_hash UNIQUE 约束）+ 异步写入 |
